# Diamond

Diamond — нативное приложение для заметок Markdown и исходного кода на Arch Linux. Rust, egui и OpenGL; ваши заметки остаются обычными файлами в обычной папке. Исходный код открыт под MIT.

Версия **0.6.0 — исходная альфа**. Это развивающийся редактор: [матрица возможностей](docs/ACCEPTANCE.md) описывает реализованный объём, [VALIDATION.md](docs/VALIDATION.md) — выполненные и ещё не выполненные проверки.

## Обновление 0.6

- Вложенные маркированные, нумерованные и смешанные списки, задачи на разных уровнях, многострочные и вложенные цитаты с inline-оформлением.
- Enter продолжает номер, маркер или незавершённую задачу в Live и Markdown Source. Новая задача всегда не выполнена. Enter на пустом пункте завершает список либо возвращает на родительский уровень; Shift+Enter оставляет обычный перенос.
- Формулы `$x^2$` и `$$\frac{1}{2}$$`: нативный mathematical-LaTeX через latex-rust и встроенный STIX Two Math, без браузера, shell и сетевых шрифтов. Формулы — структурные объекты, при редактировании раскрывается исходный TeX. Это математический режим, не полная TeX-система с пакетами/TikZ.
- Сноски `текст[^note]` и `[^note]: определение`: автоматическая нумерация по первому упоминанию, повторные ссылки используют тот же номер. Ctrl+щелчок по номеру переводит к определению. Поддерживаются обычные многоабзацные определения с inline-оформлением; сложные вложенные блоки могут оставаться исходным текстом.
- Блоки кода имеют заголовок с языком (`text`, если язык не указан) и отдельную строку пространства перед рамкой.
- Чекбоксы увеличены, получают курсор-палец и сохраняют область нажатия при смене фокуса. Выполненная задача — залитый круг с контрастной галочкой; переключение отменяется через Ctrl+Z.

0.6 подготовлена как патч к репозиторию `endstater/diamond`, базовый commit `1a495d05518e439f7df73a3d7609ad6b6f2c98ce`. На GitHub изменения не отправлены. Сохраните свои `target`, `Cargo.lock` и настройки; новая зависимость latex-rust потребует однократного разрешения Cargo.lock/загрузки. egui/eframe и MSRV Rust 1.88 не менялись.

## Что умеет

- Live Markdown: `#` для заголовков, `**` для жирного, `*` для курсива, списки, задачи, цитаты, inline-код и блоки кода. Разметка раскрывается рядом с курсором; кнопок форматирования нет.
- Таблицы GFM с заголовком, выравниванием колонок, ссылками и форматированием в ячейках. Для редактирования раскройте исходную разметку курсором. Широкие таблицы прокручиваются вместе с редактором.
- Отдельно стоящие изображения `![Alt](адрес "Подпись")`: PNG, JPEG, GIF (первый кадр), WebP. Локальные файлы из хранилища загружаются автоматически; HTTP(S) — по кнопке **Load image**. Загрузка и декодирование выполняются в фоне, ошибка сервера не изменяет Markdown. Подпись title видна при наведении.
- Круглые задачи переключаются щелчком. Изменение записывается как `[ ]` / `[x]` и отменяется через Ctrl+Z. `---` показывает горизонтальный разделитель.
- Обычные ссылки `[текст](адрес)` и `[[Заметка|подпись]]` отображаются как ссылки. Ctrl+щелчок открывает заметку; HTTP/HTTPS открываются в системном браузере. Простое открытие файла не загружает удалённый контент.
- Форматированные `.md` сохраняются автоматически через 600 мс после правки. Другие расширения открываются в исходном режиме; для нетекстовых байтов есть hex-редактор без потерь при декодировании.
- Вкладки, сворачиваемое дерево папок, разные иконки типов файлов, меню переименования файлов и удаления по ПКМ. Все папки при открытии хранилища свёрнуты. Удаление необратимо и требует подтверждения в приложении; содержимое папки и несохранённые правки затронутых вкладок также удаляются.
- Блоки с тройными обратными кавычками имеют отдельный фон и подсветку по языку после открывающего fence. Source выбирает грамматику по расширению файла. Syntect поддерживает Rust, Python, C/C++, JavaScript, HTML/CSS, JSON, SQL и другие встроенные грамматики; TypeScript пока использует JavaScript fallback. Многострочные строки и комментарии разбираются с состоянием между строками, результат кэшируется.
- Поиск по заметкам с одинаковой шириной кликабельных карточек; локальный поиск с подсветкой, регистром, regexp и заменой.
- Заголовки, задачи, теги и обратные ссылки в инспекторе, переключение недавних хранилищ.
- Изменения файлов отслеживаются через системные события inotify/notify, без периодического опроса папки. Системный выбор хранилища через XDG portal, с ручным вводом пути при недоступном портале.
- Тёмная, светлая и системная тема, акцентный цвет, отдельные шрифты и размеры текста интерфейса и редактора. Английский интерфейс по умолчанию, русский и упрощённый китайский переключаются в Settings → Language.
- Встроенный пользовательский `diamond2.svg`, локальные Lucide Icons с лицензией; для интерфейса не нужны сетевые иконки или шрифты.
- Собственная система плагинов: отдельные программы на любом языке с JSON-протоколом через stdin/stdout.

## Почему выбрать Diamond вместо Obsidian

Преимущества зависят от задачи. Diamond интересен, если вам нужны открытый код, нативный стек и собственные инструменты, написанные на удобном языке.

| Отличие | Diamond | Obsidian |
| --- | --- | --- |
| Основной desktop-стек | Rust + egui, без встроенного браузерного движка | Electron |
| Исходники приложения | Код этого проекта доступен под MIT: можно изучать и изменять | Публичный API плагинов и документация; основной редактор распространяется как готовое приложение |
| Модель плагинов | Самостоятельный процесс на любом языке с JSON по stdio; пример на Python | JavaScript/TypeScript API внутри экосистемы Obsidian |
| Заметки и произвольные файлы | Live Markdown, исходник UTF-8 и явный hex в одном приложении | Основной сценарий — Markdown и работа с базой знаний |
| Управление реализацией | Небольшой workspace с отдельными документом, файловой подсистемой, UI и хостом плагинов | Более зрелое приложение с развитой экосистемой |

Локальные Markdown-файлы и работа без обязательного аккаунта есть **у обоих** приложений. Obsidian также бесплатен для личной и коммерческой работы. Мы не заявляем преимущество по скорости, RAM или энергопотреблению без измерений. У Obsidian больше готовых возможностей, плагинов и поддерживаемых платформ; Diamond пока не является полной заменой.

Источники сравнения: официальные [используемые библиотеки Obsidian](https://obsidian.md/help/credits), [документация плагинов](https://docs.obsidian.md/), [хранение данных](https://obsidian.md/help/data-storage), [бесплатное использование для работы](https://obsidian.md/blog/free-for-work/). Сверено 21 ноября 2026 года.

## Сборка и запуск

Требуется Rust 1.88+ с Cargo, rustfmt и Clippy. На Arch установите зависимости обычным способом. Для системного выбора файлов нужен работающий `xdg-desktop-portal` с подходящим для вашего окружения backend; для выбора шрифтов — Fontconfig. Для китайского интерфейса установите `noto-fonts-cjk` и перезапустите Diamond: приложение подбирает CJK fallback через Fontconfig.

```sh
cd diamond-0.6.0
cargo run --release -p diamond-app -- ./examples/vault
```

Можно передать свою папку или конкретный файл. Если передан файл, его родительская папка становится хранилищем. Без аргумента открывается последнее хранилище либо стартовый экран. Основная сборка не требует WebKitGTK.

Первый запуск Cargo требует сети для разрешения и загрузки отсутствующих зависимостей. Сохраните созданный `Cargo.lock`.

### Обновление с сохранением кэша Rust

Закройте Diamond. Распакуйте архив поверх старой **папки исходников**, сохранив её `target` и `Cargo.lock`. Это не путь к вашему хранилищу заметок.

```sh
tar -xzf /путь/diamond-0.6.0.tar.gz --strip-components=1 -C /путь/к/старым/исходникам
cd /путь/к/старым/исходникам
cargo build --release -p diamond-app
```

Не выполняйте `cargo clean`. Используйте тот же toolchain, профиль и флаги сборки: Cargo переиспользует совместимые артефакты и пересоберёт изменённые crates и зависящие от них части. В 0.5 добавлены зависимости `syntect`, `image` и `ureq` для грамматик и нативных изображений; в 0.6 добавлена latex-rust 2.1.1 для формул. Для первой сборки обновления нужен доступ к реестру crates; `pulldown-cmark` остаётся на 0.13.6. `--locked` для первого обновления не используйте — старый lockfile должен обновиться. egui/eframe остаются на 0.33.0.

Для Arch есть [PKGBUILD и инструкция](packaging/README.md).

## Клавиши и настройки

| Действие | Клавиши |
| --- | --- |
| Открыть хранилище | Ctrl+O |
| Новая заметка | Ctrl+N |
| Поиск в документе | Ctrl+F |
| Поиск по хранилищу | Ctrl+Shift+F |
| Командная палитра | Ctrl+Shift+P |
| Отмена / повтор | Ctrl+Z / Ctrl+Shift+Z |
| Открыть ссылку | Ctrl+щелчок |
| Закрыть поиск | Esc |
| Явно сохранить текущий файл | Ctrl+S |

Настройки сохраняются автоматически в `$XDG_CONFIG_HOME/diamond/settings.json` или `$HOME/.config/diamond/settings.json`. Settings — обычная вкладка. Ползунки показывают черновое значение во время перетаскивания и применяют его после отпускания; клавиатурный ввод применяется при изменении значения. Путь к системному шрифту хранится в настройках: при переносе на другую машину выберите шрифт заново. Системные сообщения ошибок и ответы сторонних плагинов могут оставаться на языке их источника.

## Свои плагины

Плагин реализует [протокол Diamond v1](crates/diamond-plugin/README.md). Пример: [Python uppercase](examples/plugins/uppercase). Обсидиановские плагины напрямую несовместимы с этим API.

Открытие хранилища не запускает код. Манифест выбирается явно, запуск показывает команду и возможности. Передача текста документа включается отдельно; предложенную замену можно проверить перед применением. Процесс работает с правами текущего пользователя ОС — протокол не является системной песочницей.

## Сохранность и ограничения

Нетронутый Markdown сохраняется с исходными байтами, пробелами и CRLF. Неизвестные конструкции сохраняются в исходном виде; изображения внутри смешанного текстового абзаца, embeds, сложные вложенные блочные конструкции (например, таблицы/код внутри контейнеров) и HTML пока не получают полного форматированного представления. Обычные вложенные списки и цитаты представлены отдельными уровнями. Простые списки сохраняют оформление соседних пунктов при вводе незавершённого пункта или пустой строки. Неподдерживаемые блоки показываются обычным текстом, а не как inline-код. Блоки настоящего кода сохраняют оформление кода.

Сохранение сравнивает байты файла с загруженной версией, записывает временный файл рядом, выполняет fsync и атомарную замену. При конфликте текст остаётся в памяти, автосохранение останавливается. Между последней проверкой и заменой остаётся файловая гонка; межпроцессная блокировка и журнал восстановления ещё не реализованы. Файловые операции ограничены хранилищем; переходы через `..` и симлинки отклоняются.

Превью изображений ограничено 16 MiB входных байтов и размером 4096×4096; в памяти хранятся уменьшенные текстуры до 1200×1200, не более 12 записей на открытый редактор, с двумя одновременными задачами загрузки для приложения. Нет автоматической повторной загрузки при ошибке.

Переименование использует создание hard link и удаление старого имени в той же папке, без перезаписи существующего файла. Файловая система должна поддерживать hard links; при сбое между этими операциями может остаться второе имя того же файла. Грязный буфер и история не сбрасываются.

Это редактор небольших и средних документов, без виртуализации больших файлов, LSP, отладчика и мобильной версии. Чтение файла ограничено 32 MiB, индексирование Markdown — 2 MiB на заметку и 64 MiB суммарно, дерево — 50 000 записей и 64 уровня.

Sync и Publish не входят в задачи проекта. Excalidraw пока описан как отдельный необязательный помощник, но его рабочая интеграция ещё не реализована. Исправление неблокирующего EGL swap на Wayland из 0.3.1 сохранено; [диагностика Hyprland](docs/WAYLAND-0.3.1.md).

## Устройство и проверки

| Crate | Ответственность |
| --- | --- |
| `diamond-core` | Настройки, переводы, общий поиск |
| `diamond-document` | Семантический Markdown, source map, Unicode-операции и история |
| `diamond-vault` | Относительные пути, чтение байтов, сохранение, удаление и индекс |
| `diamond-editor` | Нативные редакторы Live Markdown, исходника и hex |
| `diamond-plugin` | Протокол и процессы плагинов |
| `diamond-app` | Окно, вкладки, системные сервисы и настройки |

```sh
python3 scripts/check_sources.py
python3 scripts/check_plugin_example.py
cargo fmt --all
./scripts/check.sh
```

Последний скрипт запускает Rust-тесты, Clippy и проверку дерева зависимостей на встроенный браузерный runtime. Исправлен найденный цикл немедленных repaint при потере фокуса окна; реальное потребление CPU на Hyprland после изменения ещё требует проверки. В среде подготовки этого архива Rust отсутствует: компиляция, Rust-тесты и реальное окно **не проверены**. Структурная проверка и smoke-тест Python-плагина выполнены; подробности в [VALIDATION.md](docs/VALIDATION.md).
